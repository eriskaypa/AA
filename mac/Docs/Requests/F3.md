# F3 — contract change requests (ARCHITECTURE.md §12.3)

## REQ-F3-01: `SmokeTest.run` return value semantics
Target: `Sources/AA/ShellFeatures/SmokeTest.swift` (owner W-SHELL) — ARCHITECTURE.md §7.1, §7.7
Need: document that `AAMain` calls `SmokeTest.run(options:)` before `AAApp.main()`: a non-zero result is a refusal and
the process exits with it (BD.3.12 exit 3); `0` means "harness armed" and the normal launch continues (the harness then
drives the real splash/login/main through `ShellLoginModel.shared.submit(username:password:)` and observes
`LaunchCoordinator.shared.phase`, `env.status.message`, `env.windowTitle`).
Why: ARCH §7.1 only says "--smoke-test → SmokeTest.run(options:)"; the harness must run inside the live app.
Workaround in place: `AAMain` implements exactly this rule.

Resolution: applied — `AAMain` calls `SmokeTest.run(options:)` before `AAApp.main()`: non-zero = refusal and exit code, 0 = harness armed; implemented by F3/W-SHELL (ShellXSmoke, SmokeTest) and recorded in DECISIONS "Contract amendments (post-wave)" (this docs commit)

## REQ-F3-02: where W-SHELL shows the translocation sheet (SHELL-190)
Target: `Sources/AA/ShellFeatures/*` (owner W-SHELL) — ARCHITECTURE.md §7.7
Need: no new API — `AppEnvironment.isTranslocated` (BD.3.6 detection, F3) is available; `ReminderCenter.start(env:)` is
called once when the main window shows data, after the D1/D2 alerts, and is the natural place for the once-per-launch
"Move AA to Applications" sheet (`env.mainDialogs`).
Why: SHELL-190 is W-SHELL's feature, the trigger point is F3's launch pipeline, and ARCH has no dedicated hook.
Workaround in place: none needed.

Resolution: applied — W-SHELL shows the SHELL-190 translocation sheet once per launch from `ReminderCenter.start(env:)` using `env.isTranslocated`; no API change (no commit)

## REQ-F3-03: panels register themselves with `SceneOpener`
Target: `Sources/AA/Windows/DueDatesPanelController.swift`, `QuickSwitcherPanelController.swift` (owner W-QUICK) — §7.1, §9.6
Need: the real controllers call `SceneOpener.shared.registerPanel(panel, as: .due / .switcher)` when they create their
`NSPanel` (F3 API) so the router sees the key window role, the panels are excluded from the Window menu and the snapshot
hook can render them by id (the placeholders already do this).
Why: ARCH §9.6 says the panels "register themselves the same way"; this names the call.

Resolution: applied — `QuickSwitcherPanelController` and `DueDatesPanelController` call `SceneOpener.shared.registerPanel(_:as:)` (W-QUICK); no API change (no commit)
